# Studio 3 new UI: execution checklist

**Goal:** re-skin the current Flutter app (iOS + Android) so every screen that exists today looks exactly like its board in the redesign canvas, in **both a light and a dark theme**. **No app-flow changes**: same screens, steps, navigation, API calls and business logic. The only new feature is the theme switch in Profile settings, and that is the **only backend change** (storing the user's theme choice).

**What's left (2026-10-26):** [REMAINING_UI_CHECKLIST.md](REMAINING_UI_CHECKLIST.md) lists every board, note and rule on the canvas that the app doesn't match yet, including the 20 boards added to the canvas after this plan was written.

Tick boxes as work lands (`- [ ]` → `- [x]`). A screen counts as done only when all of its boxes are ticked (note, built, light + dark, QA).

## 0. Strict replication mandate (non-negotiable)

Every screen is built **exactly as it is on the canvas**: every flow, every page, every step inside a form, every feed, every sheet and every state. That covers sign-in, home feed, explore, saved, profiles, piece pages, checkout, posting, scenes, messaging, notifications and settings. "Close enough" fails review.

### 0.2 Every screen, with its note

1. **Before building a screen, open its board and the note below it.** Notes are in `reference/Note<Board>.dc.html` and are linked from each screen in the phases below. The note is the designer's explanation of purpose, data, behaviour, states and edge cases. Build everything it describes, not only what the mock happens to show. Examples: "dots appear only with 2+ photos", "Continue stays grey until no dots remain", "the bar fades in with no border".
2. **Replicate the board as it is:** the structure, the order of elements, and every size, spacing, radius, color, font, weight, icon, label, placeholder and state.
3. **Order of precedence when sources disagree:** `HandoffRules`, then `HandoffSizes`, then the screen's note (for behaviour, states and copy), then the board's pixels. The flow freeze in section 1 still applies. If a note describes a flow change, build only the visual part and record it in the discrepancy log (0.3).
4. **Every instance follows the board.** A component drawn once (a feed card, a chip, a sheet, a row, a bubble) looks the same everywhere it appears in the app.
5. **Never improvise.** Anything not on a board or in a note follows `HandoffRules` and the closest existing board. If it is still unclear, log it and ask Abott.
6. Only three of the 99 screen boards have no note (checked after the 2026-10-21 canvas update: 96 notes, none orphaned). Each is still governed by something:
  - `NotifCatalog` is a spec table, not a screen, so the board is its own note. Its "How it looks inside the app" column and its status-color rule are the reference for the in-app rows of `NotifActivity` (Phase 9). Its triggers, push wording, bundling and text/email columns are backend work and out of scope (section 20).
  - `NotifLockScreen` draws the phone's OS lock screen, which the app never renders. Push wording comes from `NotifCatalog` and is sent by the backend: out of scope.
  - `PieceMadeWith` is archived because its "Made with" section moved onto the live piece boards (`BuyPieceFull`, `PieceNotForSale`), governed by `NoteBuyPiece` ("Body: description, Made with, …"). Build "Made with" from those boards (Phase 7, decision D7), never from the archived one.

### 0.4 How exact replication is done (and proven)

1. **Values from source, not by eye.** Read each board's `.dc.html` and copy every `font-size`, `font-weight`, `line-height`, `letter-spacing`, `padding`, `gap`, `border-radius`, color and size. The boards are 390 px wide, so **1 CSS px = 1 Flutter logical pixel**, with no conversion.
2. **Same assets.** Icons are the boards' own inline SVG paths, extracted into `assets/icons/` and drawn with `flutter_svg`, never Material look-alikes. Geist, Geist Mono and Outfit are bundled at the exact weights used.
3. **One CSS → Flutter translation**, used by everyone:

  | CSS on the board                    | Flutter                                                            |
  | ----------------------------------- | ------------------------------------------------------------------ |
  | `display:flex; gap: N`              | `Row` / `Column` with `spacing: N`                                 |
  | `font-size: F; line-height: L`      | `TextStyle(fontSize: F, height: L)` with even leading distribution |
  | `letter-spacing: X px`              | `letterSpacing: X`                                                 |
  | `linear-gradient(Adeg, …)`          | `LinearGradient` with the angle converted to begin/end alignments  |
  | `backdrop-filter: blur()`           | `BackdropFilter`                                                   |
  | `aspect-ratio`, `object-fit: cover` | `AspectRatio`, `BoxFit.cover`                                      |
  | `position: absolute`                | `Stack` + `Positioned`                                             |
  | `box-shadow`, `text-shadow`         | `BoxShadow`, `Shadow` (same offsets, blur and colors)              |

4. **Board image.** Each board is rendered to a PNG at 390 px wide with headless Chrome. The boards are static HTML/CSS, so this is exact.
5. **App image.** A Flutter golden test renders the same screen at the same size. It loads Geist and uses the **mock's own sample data** from fake services: Amara Osei, "Bodies in Color", $3,500 and flat placeholder art.
6. **Pixel and geometry diff.** The two images are compared, and the result is attached to the PR: the percent of pixels that differ, a highlighted diff image, and a geometry check. A screen passes when both pass:
  - **Pixels:** under 2% different, run with `--shift 1`, which forgives a pixel that matches within one device pixel (half a point). Chrome snaps text to whole device pixels and Flutter does not, so thin grey text otherwise counts as different without anything being misplaced. The strict number is printed too.
  - **Geometry:** every horizontal band of content (text line, rule, button) is paired with the board's, and every edge must be within 1.5 pt. The band count must match. The percentage alone is not enough: on a sparse screen a whole layout 2 pt too low changes only ~1.5% of pixels, and the geometry check catches it. 1.5 pt is the floor Flutter can reach (section 0.3, "engine limit").
7. **Overlay review.** The reviewer checks the app screenshot laid over the board at 50% opacity.
8. **Note check.** The reviewer walks through the screen's note line by line and confirms every behaviour, state and edge case is built, or logged in 0.3.
9. **Real-data check** on SE, standard and Pro Max sizes, at the largest text size, with reduced motion, in light and dark (section 19.1).

Accepted differences, and only these:

- font edge smoothing (browser vs app);
- the real status bar instead of the mock's drawn one;
- real photos and data in place of the placeholder art.

## 1. Ground rules (read before every task)

1. **Flow is frozen.** No added, removed or reordered screens, steps, tabs, routes or API calls. Buttons keep doing what they do. The single exception is the Appearance setting (Phase 2).
2. **Visual match is exact.** Colors, type, sizes, spacing, radii, icons, static copy, states and motion follow the board. Mock vs `HandoffRules` → **HandoffRules wins**. Mock pixel vs `HandoffSizes` (e.g. feed piece 470 vs rule 520) → **HandoffSizes wins**.
3. **Sheet vs screen:** if the board draws a full screen but the app uses a sheet for that step (or the reverse), keep the app's container and match the board's content inside it.
4. **Features the board doesn't show** (likes and comments on the piece page, the + on Home, the Reels and Saved tabs) stay where they are, restyled. Never remove a working feature to match a mock.
5. **Data the backend doesn't send** ("Ships in", record no., per-piece views) is hidden, never faked. `[Bracketed]` mock text is placeholder data.
6. **Theme-aware only.** Screens read colors from the theme (`StudioColors` theme extension), never `const Color(...)` or hex values. Every screen is checked in light and dark.
7. **Dark edit screens stay dark in both themes** (photo edit, video trim, cover), as the canvas rule says.
8. **Accessibility is part of "exact":** 44×44 tap targets, reduced motion stops every animation, Dynamic Type wraps instead of clipping, never color alone for status, text contrast ≥ 4.5:1 in both themes.

### Type — `lib/theme/studio_type.dart`

- **Geist** for all UI, bundled in `assets/fonts/`. Weights 400 and 500 only (500 = titles, names, buttons, selected).
- **Geist Mono** for facts only: dates, times, counts, dimensions, chips, tags, codes, record numbers. Never sentences, names, prices or shipping times.
- **Outfit 700** for the wordmark only, shipped as an SVG (light and dark versions).
- Scale: titles 24–32, headers 17–20, body 14–16, labels 13, captions 12. Prices in Geist. No width-based scaling; Dynamic Type supported.
- Line boxes match CSS: every style sets `height` with even leading. Where a board sets no `line-height`, the default is Chrome's "normal" for Geist, i.e. ascent and descent each rounded to whole pixels: `(round(1.005 × size) + round(0.295 × size)) / size` (22 px → 28, 14 px → 18). A flat 1.3 drifts about 0.6 px per line.



### Spacing, radius, size — `lib/theme/studio_metrics.dart`

- Spacing scale 4, 8, 12, 16, 20, 24, 28, 32, 48. Margins: 16 feeds/Explore, 20 profiles/piece pages, 24–28 posting/sign-in.
- Radius: 8 small buttons/thumbs · 10–12 buttons, inputs, cards · 14–18 event cards, bottom bars, provenance · 24 sheet tops · round only for chips, tags, filters, avatars, switch, floating nav. **Buttons are never pills.**
- Buttons: primary 52–54 (radius 12), inline 44, small Follow 34 (radius 8). Floating nav 64 tall, 16 from sides, 28 above bottom + safe area. Sheet ≤ 90% height.
- Template 390×844; also test 375×667 (SE, add 16 bottom padding) and 440×956. Safe-area insets, never fixed offsets.
- Cards (height from aspect ratio): feed piece full width × 4/3; feed series 80% width 3:4; Explore shelf piece 160 wide 3:4; series shelf 270×180; scene shelf 140 wide 9:16; artist tile 96 (avatar 76); Explore grid column (w − 32 − 12)/2; profile grid column (w − 40 − 16)/2 at 3:4; profile series 160×160; piece hero full width × 4/3.



### Motion

0.2–0.3 s. Selection line scales in 0.22 s. Every animation honours `MediaQuery.disableAnimations`. Dark edit screens (photo edit, video trim, cover) **crossfade in and out** of the light screens around them (HandoffRules, "Dark screens").
